# 设计思路：为什么是「skill 优先」，以及分析部分怎么办

## 1. Agent、skill、RAG 怎么选

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 自建聊天网站 + 服务器 | 界面最友好 | 要服务器、要管密钥与隐私、要长期运维 | ✗ 学生项目维持不了 |
| 完整 agent + 向量库 RAG | 看起来高级 | 教材仅约 30 个实验，向量检索反而不如“按编号精确取回”；教材有版权，不能分发 | ✗ |
| **skill 集合 + 本地工具（本项目）** | 零服务器；每位同学用自己的 Key，数据留在本机；skill 即 Markdown，同学可 PR 改进 | 界面依赖 dsh / 聊天网页 | ✓ |

分三层，难度递增、能力递增：**A 粘贴提示词 → B dsh 本地网页 + skills → C（路线图）本地小界面**。

**“RAG-lite”**：实验按编号（如 2.7）天然是一个独立章节。`tools/kb.py` 让每位同学用自己手上的教材 PDF 在本机建索引，按编号精确取回原文与页码；教材本身不进仓库。

## 2. 分析部分怎么解决

“分析”是最容易被 AI 写成空话、甚至编造的部分。我们把它拆成三层，各用最合适的手段：

1. **能算的交给代码**（`labcalc.py`）：剂量、稀释、变化率、MAP、LD50、治疗指数、AChE 活性、Fisher 检验……AI 只负责调用并解释，不心算。14 个单元测试对照教材例题。
2. **机制放进知识卡**（`knowledge/cards/`）：每个实验一页，含“机制链 / 预期现象 / 常见偏差 / 临床联系”。AI 讨论时必须沿机制链逐环解释。
3. **论证协议**（`fdu-lab-analysis`）：观察（事实）→ 对照预期 → 机制解释 → **偏差作为假设**（给验证办法）→ 局限（n、误差）→ 临床联系。禁止编造文献与数据，n=1 不下统计结论。

输入端用**对话式采集**（`fdu-lab-intake`）：学生自己的原始记录与“与讲义不同之处”是分析的真正素材；DeepSeek 视作纯文本模型，图用文字描述或读数。
输出端有**自查 skill**（`fdu-lab-review`）：数字一致、图表编号、结论有数据支撑、假设不当事实。

## 3. 对用户怎样最方便
- 医学生不想装东西 → 方案 A。
- 想要自动算数据与出文件 → 方案 B，教程里每一步都有命令。
- 不想用 AI → 方案 C 的模板同样可用。

## 4. 学术诚信
这是**写作教练**而非代笔工具：原始数据与观察必须来自你本人的实验；请按课程要求声明 AI 使用（`ai_statement` 字段会自动附在文末）。详见 [诚信说明](04-学术诚信与隐私.md)。
